# Evaluation product projection

The evaluation workspace at `/app/evaluation` reads owner-scoped prediction,
human-label, outcome, calibration, and holdout-replay records. The JSON API is
`GET`/`POST /api/evaluation`. Both methods require a verified user session;
account filters are checked against that user's accounts. Writes use the shared
same-origin guard. The API has no operator-token fallback and performs no
provider writes.

The table surfaces the stored decision and reason, raw score, risk tier,
deterministic split, selection propensity, due state, and append-only observed
metrics with their censored fields. Missing outcomes and unknown propensity stay
explicitly unknown. A human label is immutable and its reviewer identity comes
from the authenticated session, not the request body. The supported taxonomy is
`hit`, `miss`, `late_hit`, `wrong_account`, `wrong_format`, `policy_block`,
`publisher_failure`, and `cannibalization`.

The projection reads the newest 500 predictions and newest 100 replay records
for the selected account/model. It does not imply that older history is absent.

Raw scores are never named or presented as probabilities. Calibration fitting,
sample counts, reliability bins, and holdout metrics count each leakage group at
most once. Contradictory labels within a group are excluded; no averaged label
is invented. A probability is shown only when the account/model has a persisted
calibrated profile; fitting uses the calibration split and holdout scoring uses
the frozen profile. Replay metrics remain nullable when evidence is
insufficient. Holdout records are not used to refit the profile. The workspace
does not claim a causal effect from policy or challenger counterfactuals when
comparison evidence is insufficient.

No demonstration outcomes are generated by the page. Live provider behavior,
hosted deployment, historical backlog ingestion, and a causal policy/challenger
simulator remain outside this projection.
