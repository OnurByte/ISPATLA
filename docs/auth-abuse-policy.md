# Signup abuse signals

`AbuseRiskService` uses the current auth SQLite database. Each signup attempt is observed in one `BEGIN IMMEDIATE` transaction, so concurrent server processes sharing this database cannot lose or bypass the short-window count. Existing Better Auth rate limits remain the enforcement boundary; this module returns a review signal, never a signup denial.

The first-party `ispatla-device` cookie carries a random 32-byte identifier and issuance time, authenticated with a domain-separated HMAC-SHA256 using the server auth secret. It expires after 30 days, is HttpOnly, SameSite=Lax, Path=/ and Secure in production. Forged, oversized, expired, duplicate or future-issued cookies are replaced. Secret rotation invalidates old cookies. The cookie is not a browser fingerprint: no canvas, user-agent, hardware or third-party fingerprint collection is performed.

Stored fields contain only domain-separated keyed hashes of the already normalized email, opaque device id and trusted client IP when available, plus timestamps, attempt id, result, review classification and optional actual successful signup user id. There is no raw email, IP, cookie or user-agent storage or logging. The caller must not trust arbitrary forwarded IP headers. A missing IP is a null signal, not an adverse signal. Only a successful Better Auth response can bind an owner; request-supplied owner ids must never be accepted.

The observation window is 10 minutes and includes the current attempt. Review requires at least three observations of the same email together with three of the same device or IP, or five observations of both the same device and IP. Device-only or IP-only repetition is never classified for review. Even combined matches are clues, not identity proof or automatic punishment. Shared browsers, family devices, shared networks, privacy browsers and VPN/Tor use must not by themselves cause sanctions. There is no VPN/Tor detection.

Signals expire from the counting window automatically. Records older than 24 hours are eligible for deletion; every attempt deletes up to 1,000 expired rows, and the operator may invoke `pruneExpired()` periodically to drain larger backlogs without an unbounded lock. Operator review queries must filter `created_at > now - 24h`, so expired backlog is never review evidence. Do not back up/export this temporary table as persistent user history. The table has no public API or user-facing cross-account lookup; review is restricted to trusted operators with database access. Any restriction requires separate operator review and a support appeal, outside this observational service. A horizontal deployment must share one central auth store or migrate these atomic counters to its central production database; independent SQLite replicas cannot provide a global rate limit.

Integration: construct once with the existing auth database and server secret. After origin checks, call `device()` and `recordSignupAttempt()` for signup, using only the validated normalized email or null. Append a returned Set-Cookie to the response. Call `completeSignupAttempt(id, actualUserId)` only after a successful signup response, or pass null for a failed response. Email verification stays optional; domain/disposable checks and existing independent rate limits remain active. Return no signal hashes or counters in public auth responses.

## Request admission before signup validation

Signup requests use atomic admission buckets in the same SQLite database before expensive preflight: a service-wide ceiling of 100 requests per 60 seconds, followed by 5 requests per normalized email per 60 seconds using an HMAC key. Rejected email and malformed body requests cannot bypass this admission. These availability limits are separate from observational abuse signals. No device-only rejection or client-supplied IP header is used. Without a verified ingress peer address, the conservative shared ceiling can temporarily return 429 to other new users when capacity is consumed; high-volume production deployments need a verified ingress/client admission policy.
